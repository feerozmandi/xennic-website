# گزارش توسعه: ادامهٔ lab متوقف‌شدهٔ OAuth

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** خروجی فقط‌خواندنی مالک برای پروژهٔ `xennic-real-oauth-73c028764aa6`، اسکریپت دست‌اول `c619bcf550cb58933268f93ed32174289e2f284b` و bundle v1.1.2.
- **وضعیت:** مالک `SERVICES: NONE` و `LAB_HTTPS_STATUS=000` گزارش کرد. علت توقف و پروفایل استفاده‌شده در مرورگر مشخص نیست. ادامهٔ ایمن طراحی و فقط آفلاین آزموده شده؛ در Docker واقعی هنوز اجرا نشده است.

## خلاصهٔ مدیریتی

وقتی سرویس‌های lab متوقف‌اند، endpoint محلی در دسترس نیست. این شاهد علت خطای callback قبلی، وضعیت DNS پروفایل Firefox یا یکپارچگی کامل volumeها نیست. نباید از آن موفقیت یا شکست scope یا login را نتیجه گرفت.

## اقدامات و خروجی‌ها

- `scripts/restart-real-oauth-local-lab.sh` برای همان پروژه و مسیر مشخص، image، volume، Compose، فایل‌های Caddy، مالکیت فایل خصوصی و نبود container/network فعال یا باقیمانده را کنترل می‌کند. DB فقط برای بررسی ledger، وجود seed و خالی‌بودن Staff خوانده می‌شود؛ build، migration و seed مجدداً اجرا نمی‌شوند.
- فایل `lab-root.crt` گزارش‌شده از اجرای قبلی حفظ می‌شود؛ پس از راه‌اندازی Caddy، CA حجم همان lab در یک فایل موقت جدید کپی و byte-by-byte مقایسه می‌شود. اختلاف یا نبود آن پیش از prompt credential باعث توقف است، نه overwrite یا trust سیستم.
- ادامه از نسخهٔ ثابت اولیه استخراج می‌شود و فقط تغییرات صریح و بررسی‌شدهٔ مقایسهٔ CA و عمر فرآیند Firefox بر آن اعمال می‌شوند. lab تا Enter یا Ctrl-C در ترمینال اصلی فعال می‌ماند؛ خروج مستقل launcher مرورگر به‌تنهایی آن را متوقف نمی‌کند. این تغییر فرض نمی‌کند launcher علت توقف قبلی بوده است.
- پس از توقف، config موقت OAuth حذف و volumeها نگهداری می‌شوند. برای پیشگیری از حذف پروفایل در حالی که ممکن است Firefox جداگانه هنوز از آن استفاده کند، پروفایل اختصاصی جدید حذف خودکار نمی‌شود و تحت پوشهٔ خصوصی باقی می‌ماند؛ می‌تواند cookie و نشست GitHub داشته باشد و بعداً باید با بررسی امن و اطلاع مالک پاک شود. در SIGKILL یا قطع برق cleanup تضمین نیست.
- هیچ system trust، hosts یا DNS تغییر نمی‌کند. Firefox باید از پروفایل مجزا و CA محدود به آن استفاده کند. اگر config یا profile از اجرای قبلی هنوز موجود باشد، ادامه متوقف می‌شود و آنها را پاک یا overwrite نمی‌کند.

## آزمون‌ها و شواهد

| مورد | محیط و تاریخ | نتیجه |
|---|---|---|
| سرویس و HTTPS محلی | ۲۰۲۶-۱۰-۳۱، رایانهٔ مالک | `NONE` و `000` طبق خروجی؛ هیچ container در حال اجرا برای project گزارش نشد |
| بررسی restart | agent، بدون Docker | نحو shell، تست prompt، verifier، و diagnostic موفق؛ رفتار runtime تأیید نشده است |
| CA و تغییر محدود tail | agent، bundle و اسکریپت pinned و دادهٔ ساختگی | تطبیق موفق و عدم تطبیق با توقف آزمایش شد؛ فایل اصلی overwrite نشد؛ tail بدون migration و seed است |
| OAuth و callback | lab مالک | شکست قبلی گزارش شده؛ علت واقعی، scope و ادامه هنوز نامعلوم |

## ریسک‌ها و کارهای باز

- مسیر محلی فقط برای رایانهٔ مالک و loopback است و راهکار پذیرش دستگاه دوم یا DNS/TLS عمومی نیست. حساب مجاز، حساب دوم، بازپخش نشست، logout، Payload/API/Origin، رسانه، GraphQL و RTL/menu/responsive همچنان بازند.
- تشخیص callback با listener غیرمحرمانه بعد از راه‌اندازی و تلاش جدید انجام شود؛ code یک‌بارمصرف قبلی تکرار نشود. `read:org` خودکار مجاز نیست.
- ممکن است فایل، container یا volume غیرمنتظره باعث توقف fail-closed شود؛ بدون حذف عمومی یا بازسازی، فقط پیام غیرمحرمانه بررسی شود. علت خاموش‌شدن lab پیشین هنوز اثبات نشده است.

## تصمیم‌ها و درخواست از مدیرکل

طبق مجوز پیشین، از همان داده‌های آزمایشی برای ادامه استفاده شود و اطلاعات App فقط در prompt مخفی محلی وارد شود. پیش از استفاده از scope گسترده‌تر یا اقدام VPS/DNS تأیید مستقل لازم است.

## پیگیری Vault

Vault فقط خواندنی است؛ پس از روشن‌شدن علت callback و تکمیل آزمون واقعی، تصمیم‌های scope و زیرساخت در نشست جداگانه بررسی شوند.
