## خلاصه و اقدامات

ایمیج Next.js production، Compose مجزای آزمایشی PostgreSQL و media، baseline migration نسخه‌بندی‌شده، دستورهای migration/seed تک‌اجرا، healthcheck و noindex آماده شدند. حالت preview ارسال ایمیل را غیرفعال می‌کند. دربارهٔ proxy هیچ فرض یا تصمیم نهایی نشده و گزارش زیرساخت reverse proxy فعالی پیدا نکرده است. جزئیات در [برنامهٔ پیش‌نمایش](../preview-deployment-plan.md) است.

## اندازه‌گیری منابع آزمایش

اعداد از annotationهای job `production-preview` در [اجرای 41092208169](https://github.com/feerozmandi/xennic-website/actions/runs/41092208169/job/124188716993) استخراج شده‌اند؛ GitHub runner با ۴ CPU و DB و دادهٔ آزمایشی کوچک، نه VPS واقعی. مقادیر `docker stats` اندازهٔ مشاهده‌شده در یک نمونه‌اند، نه اوج تضمین‌شده یا آزمون فشار.

| فاز | مصرف مشاهده‌شده |
|---|---|
| بیکار بعد از شروع برنامه | برنامه ۹۸٫۸۴ MiB؛ PostgreSQL ۴۱٫۱۳ MiB |
| آزمون نمایندهٔ ورود، API و media | بیشینهٔ مشاهده‌شدهٔ برنامه ۱۴۰٫۳۰ MiB و PostgreSQL ۴۹٫۳۶ MiB؛ فقط یک نمونه از هرکدام |
| migration | کانتینر migration در تنها نمونهٔ ثبت‌شده ۸۶٫۸۴ MiB؛ بدون احتساب PostgreSQL هم‌زمان |
| ایمیج و build | ایمیج `483250981` بایت، حدود ۴۶۰٫۸۶ MiB. build حدود ۱۲۳٫۹ ثانیه؛ کمترین RAM آزاد کل runner نسبت به شروع حدود ۲٫۳۱ GiB کمتر و فضای آزاد دیسک حدود ۴٫۶۹ GiB کمتر شد. |

روش build نمونه‌برداری `MemAvailable` و فضای آزاد کل runner هر ۰٫۲۵ ثانیه است؛ فعالیت‌های دیگر runner و cache را هم شامل می‌شود و **مصرف اختصاصی یا اوج دقیق فرایند build نیست**. build خارج VPS برنامه‌ریزی شده است. یک نمونه از بار سبک و محدودیت‌های برنامه/DB به‌ترتیب ۵۱۲/۲۵۶ MiB کفایت منابع VPS را ثابت نمی‌کند؛ بار، هم‌زمانی، proxy، حاشیه و پایش واقعی باید جداگانه بررسی شود.

## منابع و ریسک‌ها

- گزارش زیرساخت: ۴ CPU، حدود ۵٫۸ GiB RAM و ۵۳ GiB دیسک آزاد؛ در یک نمونه ۱٫۷ GiB RAM در دسترس. کفایت VPS هنوز تأیید نشده است.
- آمار CI نمونه‌برداری محدود و مخصوص runner آزمایشی است؛ ظرفیت VPS از این عددها نتیجه‌گیری قطعی نمی‌شود.
- preview هنوز به proxy واقعی، TLS، عدم bypass، حفاظت کل مسیرها، اعتبارسنجی origin، راهبرد backup/restore، بررسی امنیت لاگ و تصمیم‌گیری دربارهٔ انتقال ایمیج نیاز دارد. خطای schema یا DB قدیمی باید بازبینی شود؛ migration تازه روی DB تولیدی موجود فرض نشده است.
- در Basic Auth، همان `Authorization` مورد استفادهٔ Payload برای Bearer مصرف می‌شود؛ آزمون محلی نشان داد دروازهٔ Basic درخواست Bearer را رد می‌کند، در حالی که Basic به‌همراه کوکی Staff عبور می‌کند؛ هیچ‌یک به‌تنهایی راهکار حفاظت نهایی نیست. آزمون proxy جداگانه در CI جایگزین انتخاب و آزمون روش احراز هویت واقعی نیست.
- تا تأیید زیرساخت و دستور جداگانه هیچ VPS یا DNS تغییر داده نشده و هیچ استقراری انجام نشده است. فرم‌ها، اتصال‌ها و انتشار عمومی خارج از محدوده باقی ماندند.

## تصمیم و پیگیری Vault

انتخاب proxy و حفاظت، مسیر registry/انتقال ایمیج، سیاست credential و backup و کفایت منابع باید با دستیار زیرساخت و مالک مشخص شوند. تغییر تصمیم‌های معماری در صورت نیاز ابتدا در نشست Vault تأیید و ثبت شود؛ Vault در این نشست تغییر نکرد.
