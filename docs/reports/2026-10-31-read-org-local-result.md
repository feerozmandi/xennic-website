# گزارش توسعه: نتیجهٔ تنظیم read:org محلی

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** خروجی مالک از اسکریپت `enable-local-read-org.py` در commit `118cbdf083e4252965006d97a55a6476bdf3d5a6` و مجوز محدود ثبت‌شده در [گزارش قبلی](2026-10-31-read-org-local-approval.md).
- **وضعیت:** تغییر تنظیم و بازراه‌اندازی gate همان lab بر اساس خروجی مالک موفق گزارش شد. اعطای دسترسی در GitHub و نتیجهٔ ورود واقعی هنوز گزارش نشده‌اند.

## اقدامات و شواهد

- checksum اسکریپت، project و policy و شبکه و تنظیمات خصوصی بررسی شدند. مالک Client ID را در prompt مخفی محلی وارد کرد و اسکریپت تطبیق آن با App مستقل را PASS داد؛ هیچ مقدار credential در خروجی ارسالی نبود.
- scope تنظیم‌شده در gate این lab به `user:email read:org` تغییر کرد. اسکریپت بازراه‌اندازی gate و پاسخ 401 به API بدون نشست را PASS گزارش کرد؛ موفقیت login، علت قطعی 403 سابق و consent واقعی GitHub از آن نتیجه نمی‌شود.
- مجوز فقط برای App آزمایشی مستقل و lab محلی است. به‌محض انجام consent، grant ممکن است پس از توقف lab در GitHub باقی بماند و پس از آزمون باید با مالک لغو شود. هیچ مجوزی برای App نهایی، gate قبلی، VPS یا DNS ایجاد نشده است.
- تلاش ورود بعدی باید از صفحهٔ sign-in تازه و در Firefox اختصاصی انجام شود؛ مالک پیش از consent نام App و scopeها را بررسی کند. هیچ callback URL، code، state، cookie، token یا credential در گزارش ثبت نمی‌شود.

## آزمون‌ها و ریسک‌ها

| مورد | زمان و محیط | نتیجه |
|---|---|---|
| تطبیق App و تنظیم scope | ۲۰۲۶-۱۰-۳۱، رایانهٔ مالک | طبق خروجی PASS؛ بدون ثبت مقدار App ID |
| بازراه‌اندازی gate و API بدون نشست | همان محیط | طبق خروجی PASS و HTTP 401؛ موفقیت auth نیست |

| حساب دوم، logout، Staff/API/Origin، رسانه، GraphQL و دو دستگاه | lab واقعی | همچنان باز است |

## تصمیم‌ها و درخواست از مدیرکل

ترمینال اصلی lab تا پایان آزمون باز بماند؛ اگر نام App یا scope نمایش‌داده‌شده مطابق مجوز نیست، consent متوقف شود. فقط نتیجهٔ غیرمحرمانهٔ ورود گزارش شود و آدرس کامل callback یا محتویات خام مرورگر فرستاده نشود.

## پیگیری Vault

Vault فقط خواندنی است؛ نتیجهٔ واقعی، scope نهایی و طرح زیرساخت پس از آزمون و تأیید در نشست جداگانه بررسی شوند.
