# گزارش توسعه: ثبت App آزمایشی OAuth

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** گزارش [آماده‌سازی OAuth واقعی محلی](2026-10-31-real-oauth-preparation.md)، نسخهٔ سایت `418de2b5b3a272e79a824ccde5411dc25f1002cc` و گفتهٔ مالک.
- **وضعیت:** مالک در گفتگو اعلام کرد App آزمایشی مستقل ساخته شده است؛ agent تنظیمات یا credentials حساب را ندیده و هیچ آزمون OAuth اجرا نکرده است.

## خلاصهٔ مدیریتی

ساخت App به گزارش مالک تکمیل شده، اما callback مؤثر، دسترسی شبکه، scope و رفتار gate واقعی هنوز تأیید runtime ندارند. هیچ تغییری در gate موجود، VPS یا DNS انجام نشده است.

## اقدامات و خروجی‌ها

- ثبت App آزمایشی مستقل، نه استفاده مجدد یا تغییر gate قبلی، طبق تأیید مالک در مرحلهٔ قبل انجام‌شده گزارش شد. هیچ Client ID، Client Secret، cookie، token یا code در Git یا گفتگو درج نشد.
- پیش از اتصال واقعی لازم است ابزار مرورگر برای یک profile مجزا و خروجی شبکهٔ آزمایشی به GitHub به‌صورت غیرمحرمانه بررسی شود. گواهی CA آزمایشی نباید به trust store اصلی سیستم وارد شود.
- `user:email` همچنان صرفاً کاندید اولیهٔ کم‌دسترسی برای آزمایش است؛ نیاز احتمالی provider به org/team یا scope بیشتر با نتیجهٔ واقعی و اطلاع‌رسانی به مالک بررسی می‌شود، نه با فرض تأیید خودکار.

## ریسک‌ها و کارهای باز

- برنامهٔ عملیاتی محلی باید جدا و بدون port عمومی، با CA و profile اختصاصی، اطلاعات محرمانهٔ محلی و سیاست شبکهٔ مشخص آماده شود؛ آزمون egress به تنهایی احراز هویت یا scope را ثابت نمی‌کند.
- پذیرش دسکتاپ و موبایل و دو دستگاه مستقل، عدم bypass، callback واقعی، replay نشست gate، DNS/TLS عمومی، backup و rollback همچنان بازند.

## تصمیم‌ها و درخواست از مدیرکل

مجوز App مستقل قبلاً دریافت شده و به درخواست مجوز جدید برای هر مرحله نیاز نیست. صرفاً نتیجهٔ غیرمحرمانهٔ پیش‌نیازهای عملیاتی و مراحل تست گزارش شود. تغییر VPS یا DNS همچنان مجاز نیست.

## پیگیری Vault

Vault فقط خواندنی است؛ پس از تصمیم و آزمون واقعی، ثبت callback، scope و طرح زیرساخت در نشست مجزا پیگیری شود.
