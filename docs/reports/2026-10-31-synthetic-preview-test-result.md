# گزارش توسعه: نتیجهٔ آزمایش ایزولهٔ gate مصنوعی

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** سایت `418de2b5b3a272e79a824ccde5411dc25f1002cc`، بستهٔ `1.1.2` در `ccbaaded6244fb9228fcce6cbe22c67b65f896b4` و اسکریپت ادامه در `5a50bcddd2654b2c20492a39fc51fe349460c496`.
- **وضعیت:** نتیجه بر اساس خروجی ارسالی مالک از رایانهٔ Linux ایشان است؛ وضعیت PR/CI در GitHub قابل مشاهده است.

## خلاصهٔ مدیریتی

آزمون Payload واقعی پشت Caddy با **gate مصنوعی**، پس از اصلاح روش اتصال در شبکهٔ داخلی، طبق خروجی مالک موفق شد و seed تکمیل شد. این نتیجه OAuth/GitHub واقعی یا پذیرش مرورگری، TLS عمومی و استقرار را تأیید نمی‌کند. هیچ تغییر VPS یا DNS انجام نشده است.

## اقدامات و خروجی‌ها

- اجرای اولیه build و migration موفق داشت اما به علت `NetworkSettings.Ports=null` در شبکهٔ داخلی پیش از bootstrap متوقف شد؛ جزئیات در [گزارش تاریخی](2026-10-31-isolated-preview-resume.md) ثبت شده است.
- اجرای ادامه از DB و image مصنوعی همان پروژه استفاده کرد؛ migration را تکرار نکرد، ledger و خالی‌بودن Staff/pages را سنجید و سرویس‌ها را بدون پورت میزبان در شبکهٔ داخلی بالا آورد. هر چهار سرویس در کنترل پورت PASS دادند. به پایان رسید و توقف project بدون حذف volume گزارش شد.
- یک Staff مصنوعی ساخته شد. Origin نامجاز رد شد؛ login مجاز، مشخصات cookie، Origin غایب با `same-origin` و بدون Fetch Metadata، logout و ابطال Bearer با `HTTP 200` و `user:null`، و login/Bearer تازه PASS بودند.
- GraphQL و upload، metadata و دریافت فایل media با gate و رد آن‌ها بدون gate در خروجی PASS بودند؛ media بازیابی‌شده غیرخالی بررسی شد، نه تطبیق byte-by-byte. seed پس از آزمون موفق اجرا شد.
- خط متنی ثابت داخل test هنوز می‌گوید آزمون اجرا نشده؛ در این اجرا این جمله قدیمی است و خروجی اجرای واقعی مالک نشان می‌دهد test اجرا شده است، نه اینکه OAuth واقعی آزموده شده باشد.

## ریسک‌ها و کارهای باز

- gate مصنوعی احراز هویت واقعی، scope، GitHub egress، revocation نشست gate و پاسخ حساب دوم را ثابت نمی‌کند. تست خروج، مختص نشست Payload است نه نشستی در OAuth2 Proxy.
- نمونهٔ OAuth محلی قبلی در بسته callback برابر `https://localhost:18443/oauth2/callback` دارد؛ سایت baseline فقط Origin `https://preview.xennic.ir` را می‌پذیرد و cookieهای host-only در دو hostname به اشتراک گذاشته نمی‌شوند. پیوند واقعی این دو در مرورگر با همان تنظیم قدیمی ثابت نشده است. نمونهٔ OAuth نهایی نیز scope و trusted proxyهای placeholder دارد و آمادهٔ اجرا نیست.
- آزمون با دو دستگاه، مرورگر، حفاظت تمام مسیرها و عدم bypass واقعی، DNS/TLS عمومی، منابع، backup و rollback همچنان باز است. `internal: true` در lab جاری امکان egress OAuth به GitHub را فراهم نمی‌کند.

## تصمیم‌ها و درخواست از مدیرکل

طبق دستور مالک مسیر Caddy + OAuth2 Proxy + GitHub OAuth برای حساب موردنظر حفظ می‌شود. اجرای محلی واقعی باید مستقل از gate قبلی، بدون انتشار عمومی و با طرح callback و شبکهٔ سازگار توسط زیرساخت انجام شود. تغییر تنظیم App موجود یا ساخت App تازه خارج از محدودهٔ مجوز محلی قبلی باید جداگانه به مالک اعلام و تأیید شود؛ هیچ credential یا OAuth code در Git یا گفتگو خواسته نشود. پس از موفقیت آزمون واقعی، طرح استقرار VPS/DNS برای تأیید ارائه شود، نه اجرا.

## پیگیری Vault

Vault فقط خواندنی باقی ماند. نتیجهٔ آزمایش و تصمیم‌های callback، scope، شبکه و زیرساخت، در صورت نیاز پس از تأیید در نشست جداگانهٔ Vault پیگیری شوند؛ این سند جانشین ثبت تصمیم رسمی نیست.
