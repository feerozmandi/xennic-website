# گزارش توسعه: خطای 403 در غنی‌سازی OAuth

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** خروجی غیرمحرمانهٔ مالک از listener دارای self-test در commit `1bd6dc547e49638456b51367d39a68908d462e11`، کد provider بستهٔ v1.1.2 و مستندات عمومی GitHub.
- **وضعیت:** مالک PASS برای self-test و سپس `SESSION_ENRICHMENT_ERROR UPSTREAM_HTTP_403` برای تلاش تازه گزارش کرد. جزئیات پاسخ upstream و endpoint آن در خروجی تشخیصی منتشر نشده‌اند.

## شواهد و تحلیل

- بررسی listener با callback ساختگی موفق بود؛ رخداد واقعی گزارش‌شده خطا در مرحلهٔ enrich session و status upstream برابر 403 را نشان می‌دهد. طبق ترتیب کد OAuth2 Proxy، این مرحله پس از تبدیل code فراخوانی می‌شود؛ این نشانهٔ ورود موفق نهایی یا تأیید حساب مجاز نیست.
- provider GitHub در نسخهٔ بررسی‌شده قبل از محدودیت username، org و teamهای کاربر را از API می‌خواند. تنظیم محلی صراحتاً فقط `user:email` دارد. یک [issue عمومی مشابه در OAuth2 Proxy](https://github.com/oauth2-proxy/oauth2-proxy/issues/2522) کمبود `read:org` را در خواندن سازمان‌ها نشان می‌دهد؛ اما چون متن و endpoint خطای فعلی با فیلتر حذف شده‌اند، این شاهد علت قطعی رخداد مالک نیست و rate limit یا سیاست‌های دیگر همچنان ممکن‌اند.
- [مستند GitHub برای scopeها](https://github.com/github/docs/blob/main/content/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps.md) `read:org` را دسترسی خواندنی به عضویت سازمان، پروژه‌های سازمان و عضویت تیم توصیف می‌کند. این دسترسی گسترده‌تر از email است و می‌تواند فراتر از یک سازمان باشد؛ grant در GitHub ممکن است پس از توقف lab باقی بماند تا مالک آن را لغو کند.
- هیچ مقدار آدرس callback، code، state، cookie، token، Client ID/Secret یا متن خام upstream در این گزارش ثبت نشده است. callback سابق نباید بازپخش شود. هیچ scope اضافی یا تغییری در سرویس قبلی، VPS و DNS انجام نشده است.

## آزمون‌ها و ریسک‌ها

| مورد | زمان و محیط | نتیجه |
|---|---|---|
| خودآزمون listener | ۲۰۲۶-۱۰-۳۱، رایانهٔ مالک | دریافت خطای state ساختگی PASS؛ نه login واقعی |
| تلاش واقعی | همان محیط | `SESSION_ENRICHMENT_ERROR UPSTREAM_HTTP_403` طبق خروجی مالک؛ endpoint و علت نامعلوم |
| مستندات و کد provider | بررسی ایستای agent | درخواست org/team و احتمال نیاز `read:org`؛ نه اثبات علت این 403 |
| احراز هویت نهایی و پوشش browser/API | lab واقعی | هنوز موفق تأیید نشده‌اند |

## تصمیم‌ها و درخواست از مدیرکل

`read:org` صرفاً برای App محلی قدیمی تأیید شده بود؛ برای App مستقل تازه یا هر استقرار نهایی خودکار مجاز نیست. باید یا تأیید صریح موقت برای این App آزمایشی گرفته شود، با توضیح دسترسی وسیع‌تر و لزوم لغو grant، یا تشخیص محدودتر بدون افزودن scope انجام شود. هیچ تغییر در gate پیشین، VPS یا DNS مجاز نیست.

## پیگیری Vault

Vault فقط خواندنی است؛ پس از تصمیم مالک و آزمون واقعی، نتیجه و scope نهایی در نشست جداگانه برای ثبت بررسی شود.
