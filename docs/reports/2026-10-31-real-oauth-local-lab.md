# گزارش توسعه: تحویل lab مستقل OAuth واقعی

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** سایت `418de2b5b3a272e79a824ccde5411dc25f1002cc`، بستهٔ `1.1.2` با SHA-256 ثبت‌شده در اسکریپت، و گزارش مالک از رایانهٔ خودش.
- **وضعیت:** ابزار candidate آماده و صرفاً ایستا بررسی شد. Docker در محیط عامل اجرا نشده و ورود واقعی، مرورگر و آزمون حساب مجاز یا غیرمجاز هنوز انجام نشده‌اند.

## خلاصهٔ مدیریتی

مالک Firefox و Chrome و نشست گرافیکی را موجود گزارش کرد؛ `certutil` موجود نیست. کانتینر موقت ایشان از طریق شبکهٔ مستقل به `github.com` و `api.github.com` پاسخ HTTPS 200 گرفت و شبکه پاک شد. این فقط شاهد دسترسی اولیه است، نه اثبات endpointهای OAuth، scope، گیت یا پذیرش مرورگر.

## اقدامات و خروجی‌ها

- `scripts/real-oauth-local-lab.sh` و helper مستقل آن، lab جدیدی با نام تصادفی و DB/media تازه ایجاد می‌کنند. image محلی app از آزمایش مصنوعی با image ID دوباره استفاده می‌شود، نه volume، محیط، Staff یا محتوای آن آزمایش. این image در زمان build قبلی طبق گزارش مالک ساخته شده؛ tag محلی به‌تنهایی اثبات رمزنگاری اتصال image به commit نیست.
- فایل‌های Caddy از ZIP با hash تأییدشده خوانده می‌شوند. تنها Caddy روی `127.0.0.1:443` منتشر می‌شود؛ برنامه و DB روی شبکهٔ داخلی backend و gate روی شبکهٔ auth داخلی و شبکهٔ egress خود قرار می‌گیرند. Caddy تنها رابط بین این دو شبکهٔ داخلی است. این جداسازی ادعای مقاومت در برابر root یا Docker administrator روی همان میزبان نیست.
- scope اولیه `user:email`، فقط username تأییدشده، callback منطبق با Origin، IP دقیق Caddy برای trusted proxy و cookie امن تنظیم می‌شوند. Caddy و OAuth2 Proxy از Docker log driver `none` استفاده می‌کنند تا logهای proxy حاوی OAuth code ذخیره نشوند. اطلاعات OAuth فقط در prompt بدون echo و فایل موقت mode 0600 خارج از Git قرار می‌گیرند؛ در خروج عادی یا Ctrl-C قابل‌پردازش فایل config و پروفایل اختصاصی حذف می‌شوند؛ در قطع برق یا SIGKILL پاک‌سازی تضمین نیست. داده‌ها، lab.env و volumeهای جدید باقی می‌مانند.
- Firefox با profile تازه، نگاشت process-local دامنه و DoH خاموش اجرا می‌شود؛ CA داخلی فقط با import دستی در همان profile trust می‌شود، نه در سیستم یا profile معمول. باید پیش از ورود نام صادرکننده بررسی شود و خطای گواهی دور زده نشود. این CA و داده‌های volume آزمایشی فقط برای استفادهٔ محلی‌اند.
- migration و seed تنها در DB تازه، پس از کنترل خالی‌بودن Staff و pages، انجام می‌شوند. بدون نشست، routeهای خانه، admin، API، GraphQL و media با TLS محلی بررسی می‌شوند. اسکریپت تحقق OAuth یا پذیرش مرورگر را به‌طور خودکار ادعا نمی‌کند.

## آزمون‌ها و شواهد

| آزمون | محیط و تاریخ | نتیجه |
|---|---|---|
| دسترسی شبکه | ۲۰۲۶-۱۰-۳۱، Docker روی رایانهٔ مالک | طبق خروجی مالک دو HTTP 200، بدون credential؛ فقط endpointهای پایه |
| پیش‌نیاز مرورگر | همان محیط | Firefox و Chrome موجود؛ certutil موجود نیست؛ نشست گرافیکی موجود |

| OAuth، TLS مرورگر، Staff و حساب دوم | اجرا نشده | نتیجه نامعلوم؛ باید پس از اجرای lab واقعی به تفکیک گزارش شود |

## ریسک‌ها و کارهای باز

- تغییرات جدید شبکه/port، OAuth2 Proxy، trust و مرورگر در runtime هنوز تأیید نشده‌اند. شکست فقط باید با نتیجهٔ غیرمحرمانه گزارش شود؛ ارسال log، URL callback، Client ID/Secret، cookie یا token ممنوع است.
- ممکن است `user:email` برای provider کافی نباشد؛ `read:org` برای App تازه تأیید نشده است. اگر دسترسی گسترده‌تر لازم شد، فرآیند متوقف و پیش از اعطای آن به مالک اعلام می‌شود.
- آزمایش دو دستگاه، حساب دوم، replay و logout gate، عملیات Payload با gate واقعی، Origin و Bearer، GraphQL، media، RTL/menu/responsive و مقاومت در برابر bypass همچنان باز است. Firefox محلی و 127.0.0.1 به خودی خود دسترسی دستگاه دوم را فراهم نمی‌کنند.
- CA داده و DB آزمایشی در volumeهای جدید باقی می‌مانند؛ پس از اتمام آزمایش باید روال پاک‌سازی خاص همین پروژه و لغو grant در GitHub به‌صورت جدا و بدون لمس داده‌های دیگر بررسی شود.

## تصمیم‌ها و درخواست از مدیرکل

پیش‌نیازهای جدید طبق گزارش مالک ثبت شد. در زمان اجرای local lab، Secret فقط در ترمینال محلی وارد شود؛ هیچ credential یا URL بازگشت در گفتگو ارسال نشود. نیازی به تأیید تکراری مرحلهٔ مجاز نیست؛ هر scope فراتر و اقدامات VPS/DNS همچنان خارج از مجوز فعلی‌اند.

## پیگیری Vault

Vault فقط خواندنی است. نتیجهٔ واقعی، scope و طرح زیرساخت پس از آزمون و تأیید، در نشست جداگانهٔ Vault پیگیری شوند.
