# پیش‌پرواز VPS و اعتبارسنجی manifest

- **تاریخ و مبنا:** ۲۰۲۶-۱۰-۳۱؛ گزارش مالک در همین گفتگو، [PR #11](https://github.com/feerozmandi/xennic-website/pull/11) و قرارداد `META-INT-140` v0.7.0.
- **وضعیت:** پیش‌پرواز اولیه فقط‌خواندنی و گزارش‌شده توسط مالک؛ deploy و پشتیبان عملیاتی هنوز راه‌اندازی نشده‌اند.

## انجام‌شده

- مالک روی VPS، Linux `x86_64` با ۴ CPU، حافظهٔ کل ۵٫۸ و available حدود ۲٫۶ GiB، swap چهار GiB و دیسک آزاد حدود ۵۳ GiB گزارش کرد. Docker `29.1.3` و Compose `2.40.3` موجودند. این یک نمونهٔ لحظه‌ای است و کفایت منابع اوج برای استقرار، migration، backup و restore را اثبات نمی‌کند.
- در خروجی مالک، سرویس‌های فعلی در حال اجرا بودند؛ listener روی ۸۰ یا ۴۴۳ دیده نشد و واحدهای systemd برای Caddy، nginx و Traefik inactive گزارش شدند. نبود edge یا آزادبودن پورت در زمان استقرار و وضعیت firewall/NAT همچنان باید راستی‌آزمایی شود. به سرویس‌های فعلی، شبکه، داده یا DNS تغییری داده نشده است.
- اتصال بدون اعتبارنامه به `https://ghcr.io/v2/` وضعیت 401 داد؛ دسترسی شبکه به endpoint مشاهده شد، اما مجوز pull ایمیج و مسیر SSH از GitHub Actions اثبات نشده است.
- پیش از تغییر این نشست، head PR شمارهٔ ۱۱ برابر `7994942c8f5fbf662db1efe524464f6d7adeb07f` بود و هر سه job PR موفق و job انتشار skipped بودند؛ آزمون digest منتشرشده در رویداد push واقعی هنوز اجرا نشده است.
- یک validator مستقل برای manifest غیرمحرمانهٔ deploy افزوده شد: repository ثابت، commit و digest با طول و قالب دقیق، `linux/amd64`، run number مثبت، حد اندازه، فیلد دقیق و رد کلید تکراری را کنترل می‌کند؛ ورودی نامعتبر را بازچاپ نمی‌کند. چهار گروه آزمون synthetic در sandbox موفق و به job `checks` افزوده شدند. این validator مجوز deploy، صحت منشأ manifest، قفل، backup یا rollback را به‌تنهایی تأمین نمی‌کند و هنوز به سرور یا workflow deploy متصل نیست.

## مانع و اقدام بعدی

- fingerprint کلید عمومی SSH از کنسول مستقل ارائه‌دهنده، endpoint/NAT و تخصیص IP هنوز تأیید نشده‌اند؛ برای اتصال خودکار `StrictHostKeyChecking` ضروری است. وضعیت حقیقی DNS authority و رکوردها نیز باز است.
- مالک وجود فضای خصوصی خارج از VPS را تأیید کرد؛ نوع دسترسی، در دسترس بودن همیشگی، مقصد دقیق، retention و امکان restore باید بدون دریافت Secret در گفتگو مشخص و آزموده شود. پیش از تغییر داده backup رمزنگاری‌شده و restore معتبر لازم است.
- اتصال deploy امن، همگام‌سازی و قفل مشترک VPS، صحت و سازگاری migration، healthcheck، rollback، GitHub Environment/branch protection و gate واقعی بازند. هیچ نتیجهٔ استقرار یا پذیرش عمومی ادعا نمی‌شود.

## Vault

قرارداد بخش ۱۰ `META-INT-140` v0.7.0 مرجع است؛ انتقال مسئولیت و شواهد اجرایی جدید در نشست جداگانهٔ Vault قابل پیگیری‌اند. Vault در این نشست تغییر نکرد.
