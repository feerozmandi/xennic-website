# سنجشِ سرریزِ افقی، رفعِ سرریزِ ۸۸۰–۹۳۰px، و بستنِ پنجرهٔ فهرستِ مسیرهای لبه

**تاریخ:** ۲۹ اکتبر ۲۰۲۶
**شاخه:** `arena/cf13d19d-xennic-website`
**PR:** [#60](https://github.com/feerozmandi/xennic-website/pull/60)

## خلاصه

سه کارِ به‌هم‌پیوسته انجام شد که همگی به یک بندِ بازِ کهنه برمی‌گشتند: **سرریز افقی در `.platform__art`**.

راهِ رسیدن به آن، پیدا کردنِ این بود که **بررسیِ سرریزِ افقی که به CI اضافه شده بود، هرگز چیزی را نسنجیده بود.**

## ۱. سنجش هرگز اجرا نشده بود

`page.evaluate` در Puppeteer تابع را به‌صورت **متن** به مرورگر می‌برد، نه خودِ تابع را. بنابراین این خط:

```js
const MEASURE = () => measureOverflow(document)
```

در صفحه به این تبدیل می‌شد:

```js
() => measureOverflow(document)   // measureOverflow is not defined
```

و صفحه با `ReferenceError` می‌ایستاد. چون خطا داخل حلقهٔ اندازه‌گیری می‌افتاد، بررسی آن را «سرریز» می‌خواند و شکست می‌داد.

یعنی `compose-smoke` در هر دو run پیشین به‌خاطر **سرریز** شکست نخورده بود — به‌خاطر **خرابیِ خودِ سنجش** شکست خورده بود.

### اصلاح

`scripts/layout-measure.mjs` اکنون یک عبارتِ خودبسنده می‌سازد که کمکی‌هایش را در خودش دارد:

```js
export function pageMeasurementSource() {
  return `(function (document) {
${describeElement.toString()}
${measureOverflow.toString()}
return measureOverflow(document)
})`
}
```

منبعِ کمکی‌ها همان منبعِ آزمون‌هاست، پس **یک** سنجش وجود دارد نه دو تا.

## ۲. دو چیزی که نقص نیستند

با کارکردِ درستِ سنجش، **۳۲۰ ترکیب** «سرریز» گزارش شد. پس از بررسی، تنها **۶ مورد** واقعی بود. دو دستهٔ دیگر نقص نبودند:

### الف) جعبه‌ای که نیایش می‌بُردد — ۴۱۶ مورد

`<g>`های نقشهٔ تک‌خطیِ پس‌زمینه (`g.grid-backdrop__lines` و `g.grid-backdrop__flow`) عرضِ ۱۸۴۵px داشتند و از پنجره بیرون می‌زدند. اما والدشان `svg.grid-backdrop__svg` است که `overflow-x: hidden` دارد: **SVG شکل‌هایش را در دستگاهِ مختصاتِ خودش می‌کشد** و می‌تواند شکلی را بسیار بیرون‌تر از پنجره بکشد در حالی که viewportِ SVG آن را از چشم پنهان می‌کند. خواننده چیزی از دست نمی‌دهد.

قاعدهٔ تازه: جعبه‌ای فقط گزارش می‌شود که **هیچ نیایشی آن را نمی‌بُرد**.

### ب) `body` و `html` توجیه نمی‌کنند — همین قاعده را محدود می‌کند

سایت عمداً `body { overflow-x: hidden }` دارد؛ همین یعنی محتوا **به‌جای اسکول‌شدن، بریده می‌شود** — و همین همان نقصی است که سنجیده می‌شود. پس اگر `body` به‌عنوان «بُرنده» پذیرفته می‌شد، هیچ‌چیز هرگز گزارش نمی‌شد. بنابراین `body` و `html` از قاعدهٔ بُریدن مستثنا هستند.

### پ) پاسخِ ۳۰۴ — ۱۱۲ مورد

صفحات `/en` و `/platform` با `304 Not Modified` پاسخ می‌دادند (کشِ مرورگر). این یعنی صفحه هست، نه اینکه صفحه نیست. حالا پذیرفته می‌شود.

## ۳. سرریزِ واقعی: `.platform__art` در ۸۸۰–۹۳۰px

پس از این اصلاح‌ها، تنها یک سرریزِ واقعی باقی ماند:

```
/ (fa) at 880px, theme dark:
  div.platform__art — left -26, right 410, width 436 (window 906)
/ (fa) at 900px, theme dark:
  div.platform__art — left -16, right 420, width 436 (window 916)
```

### ریشه

در breakpointِ `860px`:

```css
.platform__art { min-block-size: 300px; aspect-ratio: 16 / 11; }
```

- `min-block-size: 300px` در راستای بلوک
- `aspect-ratio: 16 / 11` ⇒ عرضِ لازم = ۳۰۰ × ۱۶/۱۱ = **۴۳۶.۳۶px**
- ستونِ گرید در ۹۰۰px فقط **۳۲۵.۹px** است
- `min-width: auto` (پیش‌فرضِ آیتمِ گرید) نمی‌گذارد آیتم از عرضِ محتوایش کوچک‌تر شود

پس جعبه روی ۴۳۶px می‌ماند، از ستونِ خودش بیرون می‌زند، و در چیدمانِ RTL **به چپ** می‌رود — آن‌قدر که از لبهٔ پنجره بیرون بزند و بریده شود.

### اندازه‌گیریِ تأییدکننده

| عرض | عرضِ جعبه | جای آن | نتیجه |
|---|---|---|---|
| ۸۶۰ | ۴۳۶px | ‎−۳۷..۴۰۰ | بیرون |
| ۹۰۰ | ۴۳۶px | ‎−۱۶..۴۲۰ | بیرون |
| ۱۰۲۴ | ۴۳۶px | ۴۰..۴۷۶ | درون |
| ۱۲۸۰ | ۵۲۶px | ۷۳..۵۹۹ | درون |

سرریز فقط در بازه‌ای رخ می‌داد که ستون از ۴۳۶px باریک‌تر بود **و** نزدیکِ لبهٔ پنجره.

### اصلاح

```css
.platform__art { ... max-inline-size: 100%; ... }
```

جعبه به ستونِ خودش محدود می‌شود. نسبتِ ۱۶/۱۱ هرجا جا دارد می‌ماند و هرجا جا ندارد ستون تصمیم می‌گیرد؛ تصویر در هر دو حال با `object-fit: cover` پر می‌شود.

گزینه‌های دیگر آزمایش شدند و کنار گذاشته شدند: `min-width: 0` هیچ اثری نداشت (چون `aspect-ratio` حداقلِ عرض را از راهِ `min-block-size` منتقل می‌کند)، و حذفِ `aspect-ratio` نسبت را در عرض‌های بزرگ هم از بین می‌برد.

## ۴. بستنِ پنجرهٔ دو‌نسخه‌ایِ فهرستِ مسیرهای لبه

`docs/status.md` می‌گفت route زنده اکنون هشِ `d903ae49…` دارد، ولی `scripts/preview-fixed-operations.py` هنوز پنجرهٔ `a4d844df…`/`d903ae49…` را می‌پذیرفت.

نسخهٔ بازبینی‌شده نصب و **تأیید** شده است — فایلِ روی لبه با مقدارِ بازبینی‌شده یکی است — پس پنجره کارش را کرده و بسته می‌شود. حالا فقط یک نسخه پذیرفته می‌شود و هر چیزِ دیگری مثلِ قبل رد می‌شود.

چون این ثابت‌ها در **محتوای** helper هستند، مانیفستِ کاندیدا بازمحاسبه شد:

```
SCOPE_MANIFEST = 28a1cc6a4181c12033d0f9e936222120058547d28ef40836e6ec07027109eb46
```

کپیِ مانیفست در `scripts/preview-scope-precheck.py` — که از نصب‌کننده جدا افتاده بود (`de2a97a7…` در برابر `8268b94d…`) و کاندیدای درست را رد می‌کرد — هم‌راستا شد، و آزمونی تازه این دو پین را به هم می‌بندد.

**نکتهٔ عملیاتی:** نسخهٔ helperِ روی میزبانِ زنده تا وقتی تازه نشود همان پنجره را در خود دارد. این تغییر محتوای آن را عوض می‌کند ولی **روی میزبان چیزی را عوض نمی‌کند**.

### آزمون‌های تازه

- «سنجشی که مرورگر می‌گیرد خودبسنده است» — دقیقاً همان باگ را می‌گیرد
- «سنجشِ مرورگر با سنجشِ تحت آزمون یکی است» — وگرنه بررسی چیزی را می‌سنجید که آزمون‌ها ندیده‌اند
- «جعبه‌ای که نیایش می‌بُردد نقص نیست»
- «پنهان‌کردنِ سرریز توسط خودِ صفحه، سرریز را توجیه نمی‌کند»
- «pre-check و نصب‌کننده همان کاندیدا را نام می‌برند»
