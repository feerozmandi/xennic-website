# گزارش توسعه: HTTP 500 و self-test تشخیصی OAuth

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** عدد status navigation گزارش‌شدهٔ مالک، bundle v1.1.2 و کد OAuth2 Proxy v7.15.5.
- **وضعیت:** مالک status `500` را برای صفحهٔ callback گزارش کرد. علت فنی، وضعیت جاری lab و نتیجهٔ تست مجدد هنوز نامعلوم است.

## خلاصهٔ مدیریتی

پاسخ مرورگر در دستهٔ server-side است؛ Caddy خطاهای 5xx دریافت‌شده از gate را با status و متن عمومی 500 جایگزین می‌کند. این عدد به‌تنهایی دلیل خطا یا status دقیق upstream را ثابت نمی‌کند. خطای parsing state، تبدیل code، غنی‌سازی session یا ذخیرهٔ session در کد provider نمونه‌هایی از مسیرهای ممکن‌اند، نه تشخیص قطعی. موفقیت OAuth ادعا نمی‌شود.

## اقدامات و خروجی‌ها

- listener قبلی فقط زنده‌ماندن client را پیش از `READY` چک می‌کرد و در اجرای گزارش‌شده label نداد؛ از این خروجی نمی‌توان نتیجه گرفت callback در بازهٔ اتصال اجرا شده یا stream واقعاً خطا را منتقل کرده است.
- `scripts/diagnose-real-oauth-callback.py` اکنون پیش از اعلام `READY` یک درخواست فقط‌محلی بدون cookie، authorization، code یا GitHub token به callback با state ساختگی نامعتبر می‌فرستد. طبق کد v7.15.5 این state پیش از خواندن CSRF یا تبدیل code رد می‌شود و نباید تماس GitHub یا session واقعی ایجاد کند. `curl -q` مانع بارگذاری تنظیمات و cookieهای احتمالی curl کاربر می‌شود.
- صرفاً اگر status تست ساختگی 500 و خط استاندارد ثابت خطای state از stream مشاهده شود، listener برای تلاش واقعی بعدی آماده اعلام می‌شود. در غیر این صورت fail-closed متوقف می‌شود. 500 ساختگی شاهد OAuth واقعی نیست و با 500 گزارش‌شدهٔ مالک نباید اشتباه شود.
- log driver و تنظیم gate، Caddy، مرورگر، حجم‌ها، DNS و VPS تغییر نمی‌کنند. stream خام فقط در حافظهٔ فرآیند روی رایانهٔ مالک دیده می‌شود؛ فقط label ثابت و در مورد مشخص، کد HTTP بی‌محتوای upstream چاپ می‌شود، نه URL، cookie، token، body یا لاگ خام.

## آزمون‌ها و شواهد

| مورد | محیط و تاریخ | نتیجه |
|---|---|---|
| status callback | ۲۰۲۶-۱۰-۳۱، Firefox مالک | `500` طبق عدد گزارش‌شده |
| listener قبلی | رایانهٔ مالک | هیچ رخداد قابل‌دسته‌بندی مشاهده نشد؛ اتصال و زمان‌بندی اثبات نشده |
| listener جدید | agent، Docker و curl ساختگی | خودآزمون موفق، خطای upstream فرضی، تست عدم انتشار دادهٔ ساختگی و توقف در نبود event/HTTP نامطلوب موفق؛ Docker واقعی اجرا نشده |
| OAuth و scope | lab واقعی | هنوز تأیید نشده؛ هیچ scope اضافی اعطا نشده است |

## ریسک‌ها و کارهای باز

- در صورت اعلام STOP، تلاش تازه یا scope اضافی بدون تشخیص انجام نشود. در صورت READY، فقط یک جریان ورود تازه با حساب مجاز؛ callback یا code قبلی تکرار نشود.
- callback مرورگر می‌تواند حاوی اطلاعات محرمانهٔ موقتی باشد؛ فقط label و status بی‌مقدار محرمانه ارسال شود. هیچ URL کامل، code، state، token، cookie، Client ID/Secret یا لاگ خام در مخزن یا گفتگو درخواست نمی‌شود.
- account دوم، نشست gate، Staff/API/Origin، GraphQL/media/logout، دو دستگاه و پذیرش RTL/menu/responsive باز هستند. VPS و DNS همچنان خارج از مجوزند.

## تصمیم‌ها و درخواست از مدیرکل

همان lab مستقل در حال اجرا می‌تواند برای self-test و تلاش تازه استفاده شود. نیازی به مجوز تکراری برای بررسی مجاز نیست. هر scope گسترده‌تر به هماهنگی جداگانه نیاز دارد.

## پیگیری Vault

Vault فقط خواندنی است؛ نتیجهٔ واقعی و تصمیم‌های زیرساخت و scope بعد از تکمیل آزمایش در نشست مجزا پیگیری شوند.
