# گزارش توسعه: تأیید محدود read:org محلی

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** خروجی 403 غنی‌سازی در [گزارش پیشین](2026-10-31-oauth-enrichment-403.md) و انتخاب صریح مالک در گفتگوی فعلی.
- **وضعیت:** مالک `read:org` را فقط برای App آزمایشی مستقل و همین lab محلی تأیید کرد. ابزار تغییر آماده و با داده و Docker ساختگی آزموده شد؛ هنوز در رایانهٔ مالک اجرا نشده و grant واقعی GitHub یا ورود موفق تأیید نشده است.

## تصمیم و محدوده

- `read:org` در مستند GitHub دسترسی خواندنی به عضویت سازمان‌ها، تیم‌ها و پروژه‌های سازمانی است و ممکن است به بیش از یک سازمان مربوط شود. grant در GitHub می‌تواند بعد از توقف lab باقی بماند و پس از پایان آزمایش باید با مالک برای لغو آن پیگیری شود.
- تأیید مالک فقط به App مستقل جدید و پروژهٔ `xennic-real-oauth-73c028764aa6` محدود است؛ هیچ scope نهایی یا تغییری در gate قبلی، VPS و DNS مجاز نشده است. علت دقیق 403 و endpoint هنوز اثبات نشده‌اند؛ ممکن است scope بیشتر به‌تنهایی مشکل را رفع نکند.

## اقدامات و حفاظت‌ها

- `scripts/enable-local-read-org.py` بدون نمایش مقادیر حساس، Docker محلی، شناسهٔ project و service، image، شبکه، پورت، mount فقط‌خواندنی، log driver، hash Compose و policy config را کنترل می‌کند. Client ID به‌صورت مخفی و فقط در ترمینال محلی با ID خوانده‌شده از config مقایسه می‌شود؛ مالک باید آن را از تنظیمات **App مستقل جدید** بردارد. Client Secret مجدداً درخواست نمی‌شود.
- تنها خط scope از `user:email` به `user:email read:org` در فایل خصوصی همان lab تغییر می‌کند؛ کلید cookie و Client ID/Secret و allowlist تغییر نمی‌کنند. فقط gate با `--no-deps` و بدون build یا pull بازایجاد می‌شود. app، DB، Caddy و سایر پروژه‌ها هدف تغییر نیستند.
- پس از بازایجاد، هویت gate، شبکه و پورت‌ها، ثابت‌ماندن Caddy و پاسخ 401 بدون نشست بررسی می‌شوند. در شکست یا وقفهٔ قابل‌پردازش، scope قبلی و gate قبلی بازگردانده و نتیجه گزارش می‌شود؛ در قطع برق، SIGKILL یا خطای rollback این تضمین وجود ندارد و ممکن است فایل موقت خصوصی باقی بماند.
- این ابزار خود grant را در GitHub انجام نمی‌دهد. در صفحهٔ consent باید نام App مستقل و دسترسی‌های درخواستی بررسی شوند؛ اگر App یا scope دیگری نمایش داده شود، مالک عملیات را متوقف کند. هیچ URL callback، code، state، cookie، token یا credential به گفتگو یا Git وارد نمی‌شود.

## آزمون‌ها و شواهد

| مورد | محیط و تاریخ | نتیجه |
|---|---|---|
| اجازهٔ read:org محلی | ۲۰۲۶-۱۰-۳۱، پاسخ مالک | صریحاً فقط برای App مستقل و lab؛ نه VPS یا App نهایی |
| policy و rollback | agent، Python و مقادیر ساختگی | تغییر تک‌خطی، رد policy/IP/App اشتباه، بازگشت و گزارش rollback ناموفق آزموده شد |
| اجرای سرتاسری | agent، Docker و curl ساختگی | فقط gate هدف، پاک‌سازی overrideهای محیط، عدم echo ID و عدم چاپ مقادیر ساختگی و بازگشت در شکست آزموده شد |
| Docker واقعی، consent و OAuth | رایانهٔ مالک | اجرا نشده؛ وضعیت نامعلوم |

## ریسک‌ها و کارهای باز

- کد و state موقتی callback نباید مجدداً اجرا یا ارسال شوند؛ تلاش بعدی از sign-in تازه آغاز می‌شود. عدم تطبیق App ID یا هر STOP باید بدون تلاش کورکورانه گزارش شود.
- پس از login باید حساب مجاز/دوم، session gate، Staff/API/Origin، GraphQL، media، logout، دو دستگاه و RTL/menu/responsive بررسی شوند. هیچ استقرار، رکورد DNS یا grant نهایی نتیجه‌گیری نمی‌شود.

## پیگیری Vault

Vault فقط خواندنی باقی می‌ماند. نتیجهٔ واقعی و تصمیم scope نهایی و برنامهٔ VPS پس از آزمون و تأیید در نشست مستقل پیگیری شوند.
