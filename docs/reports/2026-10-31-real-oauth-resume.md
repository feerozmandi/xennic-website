# گزارش توسعه: اصلاح prompt و ادامهٔ lab واقعی

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** خروجی مالک از اسکریپت commit `c619bcf550cb58933268f93ed32174289e2f284b` در رایانهٔ Linux ایشان و بررسی مستقل کد.
- **وضعیت:** ادامه آماده و به‌صورت آفلاین آزموده شد؛ Docker و OAuth توسط agent اجرا نشدند و نتیجهٔ اجرای ادامه نزد مالک هنوز نامعلوم است.

## خلاصهٔ مدیریتی

طبق خروجی مالک، پروژهٔ جدید بدون تغییر دادهٔ پروژهٔ پیشین ایجاد شد؛ PostgreSQL، migration، seed، app، Caddy و کنترل پورت‌ها موفق بودند. کار پیش از نمایش prompt محرمانه متوقف شد. OAuth، مرورگر، gate واقعی و حساب‌ها آزمایش نشدند. حجم‌های پروژهٔ تازه حفظ شده‌اند.

## علت و اصلاح

- helper قبلی `/dev/tty` را در حالت متنی `r+` باز می‌کرد. در یک PTY لینوکسی مستقل، همین عبارت با `UnsupportedOperation: File or stream is not seekable` شکست؛ خروجی مالک، که هیچ prompt نشان نمی‌دهد، با این علت سازگار است. خطای داخلی قبلی عمداً عمومی بود، بنابراین صرف خروجی مالک جزئیات exception را مستقلاً اثبات نمی‌کند.
- اکنون خروجی prompt از tty در حالت نوشتن استفاده می‌کند؛ `getpass` ورودی tty را جدا باز می‌کند و echo را غیرفعال می‌کند. هشدار fallback به حالت echo همچنان خطا است. هیچ credential واقعی در تست‌ها استفاده نشد.
- در بررسی ایستا، خطر تقدم متغیرهای صادرشدهٔ shell بر `--env-file` نیز شناسایی شد. اجرای جدید و ادامه متغیرهای مرتبط با DB، image و Compose را پیش از اجرای Compose از محیط حذف می‌کنند تا مقادیر فایل خصوصی تأییدشده ملاک باشند. نمی‌توان از خروجی قبلی نبود همهٔ متغیرهای محیطی مالک را اثبات کرد؛ بااین‌حال migration و seed و کنترل پروژه و شبکهٔ جدید طبق خروجی به موفقیت رسیدند.
- ادامه فقط پروژهٔ `xennic-real-oauth-73c028764aa6` و پوشهٔ مشخص گزارش‌شدهٔ مالک را می‌پذیرد؛ برچسب volumeها، نبود container و network موجود، hash اسکریپت اولیه و ZIP، image ID و Compose و فایل‌های Caddy و خصوصی را بررسی می‌کند. مقصد DB باید دقیقاً سرویس `postgres` همین پروژه باشد.
- ادامه ledger و seed و نبود Staff را می‌سنجد، اما migration و seed را تکرار نمی‌کند و محتوای موجود را بازنویسی نمی‌کند. ادامهٔ اجرایی پس از این بررسی‌ها از اسکریپت اولیهٔ hash-pinned استخراج می‌شود؛ helper prompt اصلاح‌شده استفاده خواهد شد.

## ریسک‌ها و کارهای باز

- این ادامه فقط برای پروژه و مسیر مشخص‌شده مناسب است؛ هر نبود فایل، volume، تفاوت config یا DB غیرمنتظره باید متوقف شود، نه با بازسازی یا پاک‌سازی عمومی رفع شود.
- scope، حساب مجاز/دوم، TLS و DNS عمومی، replay و logout gate، آزمون Payload با gate واقعی، دستگاه دوم و RTL/menu/responsive همچنان بازند. CA و داده‌های جدید فقط محلی‌اند.
- خروج عادی یا Ctrl-C قابل‌پردازش config و profile تازه را حذف می‌کند؛ قطع برق یا SIGKILL ممکن است منابع یا داده‌های حساس را باقی بگذارد. لاگ‌های gate و Caddy ذخیره نمی‌شوند و تشخیص خطا باید بدون افشای URL، cookie یا credential باشد.

## تصمیم‌ها و درخواست از مدیرکل

طبق مجوز قبلی می‌توان همان lab را ادامه داد؛ نیازی به مجوز جداگانه برای رفع نقص نیست. استفاده از scope بیشتر و اقدامات VPS/DNS همچنان نیازمند تأیید جداگانه است. اطلاعات محرمانه تنها در ترمینال محلی و بدون echo وارد شوند.

## پیگیری Vault

Vault فقط خواندنی است. پس از آزمون واقعی، نتایج و تصمیم‌های زیرساخت و scope در نشست جداگانه بررسی شوند.
