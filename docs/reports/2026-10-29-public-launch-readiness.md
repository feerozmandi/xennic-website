# آمادگی راه‌اندازی عمومی — ۲۰۲۶-۱۰-۲۹

## وضعیت و شاهد

مالک خواست سایت عمومی روی `https://xennic.ir` راه‌اندازی شود و اعلام کرد مقصد SFTP برای backup خارج VPS در اختیار ندارد؛ سپس گزارش کرد پشتیبانی مسئول backup است و خواست کار سایت بدون پرداختن اضافی به امور جانبی پیش برود. محدوده، محل نگهداری و امکان بازیابی backup پشتیبانی هنوز مستقلاً مشخص نشده و این گزارش به‌تنهایی جایگزین شاهد backup عملیاتی نیست. تصمیم جدید، HTTPS برای خود سایت را تغییر نداده است. [PR #24](https://github.com/feerozmandi/xennic-website/pull/24) با commit `d19c7c58302226c9fd76334f8e9587efcc1b7003` ادغام شد؛ [انتشار dev run 166](https://github.com/feerozmandi/xennic-website/actions/runs/42691292301) با شش job موفق است. [تأیید مستقل](https://github.com/feerozmandi/xennic-website/actions/runs/42693878103/job/129420437245) تطبیق commit، run، artifact و digest `sha256:a21da442a6ca58851b0618975377cbfb60dbbc4f19d7237edd426c1644a38fad` را تأیید کرد؛ job موقت از پیش‌نویس حذف شد. در این نشست هیچ DNS، سرویس یا داده‌ای تغییر نکرده و deployment، migration و seed عملیاتی انجام نشده‌اند. ساعت محیط/GitHub و تاریخ نشست اختلاف تأییدنشده دارند.

## ادامهٔ آماده‌سازی دروازه

در همین gateway موجود، فهرست محدود صفحات مصوب و assetهای Next برای GET/HEAD با host دقیق `xennic.ir` به‌صورت پیشنهادی عمومی می‌شود؛ سایر درخواست‌ها از جمله admin، API/GraphQL، media، مسیر ناشناخته و سایر hostها همچنان از gate می‌گذرند. listener خارجی هنوز فقط `preview.xennic.ir` است؛ این تغییر به‌تنهایی سایت دامنهٔ اصلی را فعال نمی‌کند. آزمون با Caddy و برنامهٔ واقعی اما gate و دادهٔ مصنوعی در CI تعریف شده است. [CI 42695260169](https://github.com/feerozmandi/xennic-website/actions/runs/42695260169) و اجرای تشخیصی ناموفق بودند: در آزمون، Node fetch سربرگ Host ارسالی را با نشانی واقعی fixture جایگزین می‌کرد و در نتیجه matcher دامنه فعال نمی‌شد. آزمون و probeهای زنجیره نصب‌شده برای ارسال واقعی Host اصلاح شدند. [CI 42699687886](https://github.com/feerozmandi/xennic-website/actions/runs/42699687886) برای همان اصلاح موفق شد؛ Caddy و برنامه واقعی ولی gate و داده‌ها مصنوعی بودند. آزمون پوشش همهٔ صفحه‌های فهرست‌شده، HEAD و asset واقعی HTML نیز اضافه شده و نتیجهٔ آن جداگانه لازم است. مسیر هنوز برای استقرار پذیرفته نیست. ارتقای محدود installer باید فایل route قبلی را نگه دارد و هنگام شکست آن را بازگرداند؛ این کار روی VPS انجام نشده است. دسترسی عمومی رسانه، مسیرهای دیگر و داده‌های خصوصی از این تغییر نتیجه نمی‌شود.

## موانع واقعی، نه مجوز دور زدن

- نسخهٔ فعلی gateway و عملیات ثابت برای `preview.xennic.ir` و gate تمام مسیرها طراحی شده‌اند. تغییر origin برنامه در PR #24 به‌تنهایی سایت عمومی آماده نمی‌کند. جداسازی درست صفحه/asset عمومی از مدیریت، API/GraphQL، Staff، media و اطلاعات خصوصی، بدون تضعیف حفاظت، نیازمند بازبینی و آزمون است. بررسی کد نشان داد مجوز read مجموعهٔ media عمومی است؛ همهٔ رسانه‌ها نباید بدون تصمیم و طبقه‌بندی عمومی فرض شوند.
- exception فعلی backup فقط staging فاقد دادهٔ واقعی را پوشش می‌دهد؛ production به backup خودکار، رمزنگاری‌شده و هماهنگ DB/media در مقصد خارج VPS و restore آزمایشی نیاز دارد. نبود مقصد اعلام‌شده مانع انتشار production است؛ ذخیره روی همان VPS یا marker انتقال دستی جایگزین آن نیست. هیچ خریدی بدون تأیید مالک انجام نمی‌شود.
- `META-INT-140` v0.7.0 §۱۰ در Vault مرجع مستقل فقط‌خواندنی و مخصوص preview خصوصی است و صراحتاً apex و سایت عمومی را خارج محدوده می‌داند. تصمیم جدید مالک باید در نشست مستقل مدیریت پروژه در Vault ثبت و دامنهٔ مسیرهای عمومی/خصوصی تعیین شود. این گزارش مجوز دور زدن قرارداد یا نوشتن در Vault نیست.
- حساب SSH محدود، اتصال Actions، ارتقای نسخهٔ جدید helper روی VPS، محافظت واقعی و تست TLS/OAuth و تداخل ۸۰/۴۴۳ هنوز نیازمند اجرا و اثبات‌اند. پاسخ resolver مبنی بر `185.192.113.85` اثبات listener، NAT، TLS، نبود سرویس دیگر یا مالکیت وب نیست. تداخل با سرویس‌های موجود یا تغییر سایر رکوردهای DNS بدون بررسی و مجوز جداگانه مجاز نیست.

## ادامه

تأیید انتشار و آمادگی اجزایی که به مقصد backup یا تصمیم معماری وابسته نیستند می‌تواند موازی ادامه یابد. برای انتشار واقعی، مقصد backup مناسب و تصمیم مدیریت دربارهٔ مسیرهای عمومی/خصوصی لازم‌اند؛ هیچ secret یا لاگ خامی نباید در گفتگو دریافت شود. `www`، ایمیل، داده‌ها و سرویس‌های موجود حفظ می‌شوند.
