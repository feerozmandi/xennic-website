# آمادگی راه‌اندازی عمومی — ۲۰۲۶-۱۰-۲۹

## وضعیت و شاهد

مالک خواست سایت عمومی روی `https://xennic.ir` راه‌اندازی شود و اعلام کرد مقصد SFTP برای backup خارج VPS در اختیار ندارد. تصمیم جدید، HTTPS برای خود سایت را تغییر نداده است. [PR #24](https://github.com/feerozmandi/xennic-website/pull/24) با commit `d19c7c58302226c9fd76334f8e9587efcc1b7003` ادغام شد؛ [انتشار dev run 166](https://github.com/feerozmandi/xennic-website/actions/runs/42691292301) با شش job موفق است. تأیید مستقل این نوک در حال اجراست. در این نشست هیچ DNS، سرویس یا داده‌ای تغییر نکرده و deployment، migration و seed عملیاتی انجام نشده‌اند. ساعت محیط/GitHub و تاریخ نشست اختلاف تأییدنشده دارند.

## موانع واقعی، نه مجوز دور زدن

- نسخهٔ فعلی gateway و عملیات ثابت برای `preview.xennic.ir` و gate تمام مسیرها طراحی شده‌اند. تغییر origin برنامه در PR #24 به‌تنهایی سایت عمومی آماده نمی‌کند. جداسازی درست صفحه/asset عمومی از مدیریت، API/GraphQL، Staff، media و اطلاعات خصوصی، بدون تضعیف حفاظت، نیازمند بازبینی و آزمون است. بررسی کد نشان داد مجوز read مجموعهٔ media عمومی است؛ همهٔ رسانه‌ها نباید بدون تصمیم و طبقه‌بندی عمومی فرض شوند.
- exception فعلی backup فقط staging فاقد دادهٔ واقعی را پوشش می‌دهد؛ production به backup خودکار، رمزنگاری‌شده و هماهنگ DB/media در مقصد خارج VPS و restore آزمایشی نیاز دارد. نبود مقصد اعلام‌شده مانع انتشار production است؛ ذخیره روی همان VPS یا marker انتقال دستی جایگزین آن نیست. هیچ خریدی بدون تأیید مالک انجام نمی‌شود.
- `META-INT-140` v0.7.0 §۱۰ در Vault مرجع مستقل فقط‌خواندنی و مخصوص preview خصوصی است و صراحتاً apex و سایت عمومی را خارج محدوده می‌داند. تصمیم جدید مالک باید در نشست مستقل مدیریت پروژه در Vault ثبت و دامنهٔ مسیرهای عمومی/خصوصی تعیین شود. این گزارش مجوز دور زدن قرارداد یا نوشتن در Vault نیست.
- حساب SSH محدود، اتصال Actions، ارتقای نسخهٔ جدید helper روی VPS، محافظت واقعی و تست TLS/OAuth و تداخل ۸۰/۴۴۳ هنوز نیازمند اجرا و اثبات‌اند. پاسخ resolver مبنی بر `185.192.113.85` اثبات listener، NAT، TLS، نبود سرویس دیگر یا مالکیت وب نیست. تداخل با سرویس‌های موجود یا تغییر سایر رکوردهای DNS بدون بررسی و مجوز جداگانه مجاز نیست.

## ادامه

تأیید انتشار و آمادگی اجزایی که به مقصد backup یا تصمیم معماری وابسته نیستند می‌تواند موازی ادامه یابد. برای انتشار واقعی، مقصد backup مناسب و تصمیم مدیریت دربارهٔ مسیرهای عمومی/خصوصی لازم‌اند؛ هیچ secret یا لاگ خامی نباید در گفتگو دریافت شود. `www`، ایمیل، داده‌ها و سرویس‌های موجود حفظ می‌شوند.
