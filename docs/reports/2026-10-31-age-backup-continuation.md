# ادامهٔ فرمت age و مسیر اجرایی پیش‌نمایش

- **تاریخ:** ۲۰۲۶-۱۰-۳۱؛ [PR #13](https://github.com/feerozmandi/xennic-website/pull/13). SSH/deploy غیرفعال و VPS/DNS بدون تغییر مانده‌اند.
- **نتیجه:** فرمت آزمایشی AES مرحلهٔ قبل کنار گذاشته شد و کد مشترک `scripts/preview-age-backup.py` بستهٔ age شامل dump، media، commit برنامه، ledger مهاجرت و فهرست/hash فایل‌های media تولید و اعتبارسنجی می‌کند. این یک کتابخانهٔ واقعی فرمت است، نه helper نصب‌شدهٔ backup و نه اتصال کامل controller. مسیر عملیاتی هنوز کامل نیست.

## آزمون و حدود

- بسته ابتدا با `age` رمز می‌شود و بازیابی قبل از انتشار فایل‌های restore، احراز صحت age، فهرست، مسیرها و hashها را بررسی می‌کند. کلید اشتباه و ciphertext تغییرکرده باید متوقف شوند. آرشیو یا خروجی DB/media قبل از authentication یا پس از آن، در پوشهٔ خصوصی موقت plaintext دارد؛ پاک‌سازی عادی انجام می‌شود ولی تضمین پاک‌سازی در قطع برق یا توقف اجباری وجود ندارد. نیاز به پوشهٔ حفاظت‌شده و سیاست پاک‌سازی در نصب عملیاتی برقرار است.
- `scripts/ci-restore.sh` در Docker دورریختنی DB و media را واقعاً dump می‌کند؛ کد همان کتابخانهٔ age را با کلید مصنوعی اجرا و خروجی آن را به پروژهٔ جدا restore می‌کند. اسکریپت CI در حال حاضر خود dump و اعمال restore را اجرا می‌کند؛ این آزمون helper ممتازِ backup/restore یا SFTP عملیاتی نیست. adapter بازگشت مرحلهٔ قبل نیز همچنان جدا از backend عملیاتی است.
- آزمون‌های محلی قالب و مسیرهای ناامن Python انجام شده‌اند؛ Docker و نصب runtime در Arena انجام نشده است. نتیجهٔ Docker و کلید آزمایشی در CI همین PR بررسی می‌شود؛ تا آن زمان موفقیت آن فرض نمی‌شود.
- شاهد انتشار قبلی [41194829543](https://github.com/feerozmandi/xennic-website/actions/runs/41194829543) فقط به commit `397d505e4214f8c5c2270189ae8e7384905609ec` و digest ثبت‌شده در [گزارش قبلی](2026-10-31-deploy-backend-continuation.md) مربوط است؛ به این commit تعمیم نمی‌یابد.

## موانع و راه‌حل‌های مشخص

1. **کد ناقص — helper و نصب:** `FixedRunner` به فایل‌های root-owned ثابتی نیاز دارد که هنوز ارائه و نصب نشده‌اند. راه‌حل: پیاده‌سازی آن ورودی‌های ثابت با نصب‌کنندهٔ root-owned و اجرای همان فایل‌ها در runner دورریختنی؛ درخواست deploy هرگز مسیر یا دستور دلخواه تعیین نکند.
2. **کد ناقص — backup عملیاتی:** ارتباط snapshot هماهنگ، انتقال و بازخوانی SFTP با host key pinned، و restore واقعاً ایزوله به controller هنوز ساخته نشده است. راه‌حل: wrapper ثابت برای توقف نویسنده‌ها، dump/media، کتابخانهٔ age، انتقال و بازخوانی/restore و آغاز migration فقط پس از موفقیت؛ با SFTP دورریختنی CI تست شود.
3. **کد ناقص — هویت انتشار:** نتیجهٔ موفق قبلی برای انتشار جدید شاهد نیست و خلاصهٔ فعلی workflow به‌تنهایی یک منبع قابل‌مصرف مطمئن برای verifier سرور فراهم نمی‌کند. راه‌حل: workflow پس از pull/test موفق، رکورد digest/commit/run/معماری را به artifact همان run بنویسد؛ helper فقط run موفق push به `dev` و artifact همان run را از GitHub بررسی و با digest pull و image ID در حال اجرا تطبیق دهد. اجرای زندهٔ انتشار جدید فقط پس از push به dev ممکن است؛ در PR باید fixtures و عدم دسترسی به اسرار عملیاتی صریح بمانند.
4. **کد ناقص — سازگاری migration:** بازگشت تصویر قدیمی به‌خودی‌خود سازگاری schema را ثابت نمی‌کند. راه‌حل محافظه‌کارانه: انتشار عادی با migration تغییرکرده یا تأییدنشده را پیش از تغییر داده متوقف کند؛ migration جداگانه با backup و برنامهٔ سازگاری لازم است.
5. **تنظیمات و دسترسی مالک:** fingerprint SSH مستقل، مقصد خصوصی خارج VPS، کلید/هویت age، اطلاعات اتصال backup و تنظیمات امن باید در زمان مناسب به‌صورت امن فراهم شوند؛ هیچ‌کدام در این مرحله درخواست یا فرض نشده‌اند. Vault جدا و فقط‌خواندنی است؛ توافق مقصد و هر تغییر قراردادی در نشست Vault پیگیری شود.
