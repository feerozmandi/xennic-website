# تغییر مقصد درخواستی به سایت عمومی روی دامنهٔ اصلی — ۲۰۲۶-۱۰-۲۹

## تصمیم و شواهد

مالک پس از بررسی محدودیت پنل DNS درخواست کرد به جای زیردامنهٔ پیش‌نمایش، سایت روی دامنهٔ اصلی `xennic.ir` باشد و در پاسخ به پرسش دسترسی، گزینهٔ «عمومی» را انتخاب کرد. این تصمیم به خودی خود مجوز انتشار APIهای مدیریتی، دادهٔ مشتری، تغییر سایر رکوردها، توقف سرویس موجود یا حذف حفاظت پنل مدیریت نیست. تصمیم دربارهٔ HTTP پنل DNS مربوط به خود پنل بود؛ برای سایت مسیر HTTPS موردنظر باقی مانده است.

در بررسی resolver این محیط، `xennic.ir` و `www.xennic.ir` هر دو `185.192.113.85` و `preview.xennic.ir` خطای resolution داشتند. این پاسخ تأیید delegation، دسترس‌پذیری خارجی، نبود سرویس موجود، صحت zone یا گواهی نیست. مالک فهرست رکوردهای zone را از پنل گزارش کرد؛ تغییری در DNS یا سرویس‌ها در این نشست انجام نشده است. `www`، ایمیل، apex و NS نباید تغییر داده یا مالکیت ترافیک آن‌ها بدون بررسی فرض شود.

[انتشار dev run 160](https://github.com/feerozmandi/xennic-website/actions/runs/42667416928) و [verifier مستقل](https://github.com/feerozmandi/xennic-website/actions/runs/42670290718/job/129344718019) برای commit `ac926714533265677a09a33a8185ae0e64f59c3a` و digest `sha256:1d98dfaf657932a27cf86fb414476882396236fe24bf223563b2376ea5a11d08` موفق بودند. این انتشار مختص preview خصوصی است، نه نسخهٔ آمادهٔ دامنهٔ اصلی یا سایت عمومی. برنامه، origin، callback OAuth، Caddy، سیاست gate، helper و قرارداد installer به دامنهٔ preview مقیدند. هیچ استقرار، migration، seed یا راه‌اندازی واقعی در VPS گزارش نشده است.

## آماده‌سازی محدود در پیش‌نویس

در پاسخ به دستور مالک برای ادامهٔ کار روی دامنهٔ اصلی، کنترل origin برنامه برای پذیرش یکی از دو مقدار دقیق HTTPS به‌صورت انتخابی اصلاح شد: دامنهٔ اصلی یا preview، هر بار فقط همان origin انتخاب‌شده برای Payload CORS، CSRF و بررسی ورود Staff مجاز است. `www`، HTTP، origin دلخواه و origin محیط دیگر مجاز نمی‌شوند؛ کوکی امن و host-only حفظ شده است. آزمون محلی تنظیمات، TypeScript و lint موفق بودند. این تغییر صرفاً آماده‌سازی برنامه در PR است: gateway هنوز همهٔ مسیرها را خصوصی می‌کند و تنظیمات عملیاتی، installer و سیاست backup دامنهٔ اصلی را نمی‌پذیرند؛ نشر عمومی و تغییر روی VPS مجاز یا انجام نشده است. CI و بازبینی مدیریت پروژه/Vault همچنان لازم‌اند.

## موانع و پیگیری

Vault مستقل و فقط‌خواندنی `META-INT-140` v0.7.0 §۱۰ به‌صراحت preview خصوصی روی `preview.xennic.ir` را تعریف و دامنهٔ اصلی و انتشار عمومی را خارج از محدوده اعلام کرده است. مدیریت پروژه باید تصمیم جدید مالک و محدودهٔ دقیق دسترسی عمومی را در نشست جداگانهٔ Vault ثبت و ابهام‌های معماری مسیر انتشار را تعیین کند؛ این مخزن مرجع موازی یا مجوز تضعیف gate نیست. صفحه‌های تأییدشده و assetهای لازم باید از admin، API/GraphQL، Staff، رسانهٔ غیرعمومی و دادهٔ مشتری تفکیک و با موارد مجاز و نامجاز آزموده شوند. HTTP برنامه صرفاً redirect/صدور گواهی می‌ماند و HTTP عمومی read-only جایگزین بدون تصمیم تازه نیست.

سیاست `manual-local` کنونی فقط برای staging بدون دادهٔ واقعی پذیرفته شده و برای production کافی نیست. پیش از انتشار عملیاتی، backup هماهنگ و رمزنگاری‌شدهٔ DB/media، مقصد خصوصی خودکار خارج VPS و restore آزمایشی معتبر لازم‌اند؛ هیچ مقصدی صرفاً بر اساس وجود marker یا فایل تنظیمات فرض نمی‌شود. قبل از اتصال ۸۰/۴۴۳، listener و NAT، دامنه و سرویس‌های موجود دوباره بررسی می‌شوند؛ n8n، بله، Open Notebook، ایمیل و داده‌ها محفوظ‌اند. SSH محدود و workflow، callback و origin مناسب، صدور و اعتبار واقعی HTTPS، policy عمومی/خصوصی و تست مرورگر همچنان آماده نیستند. هر merge جدید نیازمند publication و verifier نوک dev جدید است.
