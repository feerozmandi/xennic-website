# گزارش توسعه: تحویل اسکریپت آزمایش ایزولهٔ پیش‌نمایش

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** نسخهٔ سایت `418de2b5b3a272e79a824ccde5411dc25f1002cc`، بستهٔ زیرساخت `1.1.2` در کامیت `ccbaaded6244fb9228fcce6cbe22c67b65f896b4` از Vault، و گزارش غیرمحرمانهٔ مالک دربارهٔ رایانهٔ محلی.
- **وضعیت:** تغییر در شاخهٔ این نشست؛ وضعیت PR و CI را در GitHub بررسی کنید.

## خلاصهٔ مدیریتی

اسکریپت آزمون مصنوعی محلی برای دانلود در مخزن قرار گرفت. ساخت فایل و بررسی syntax به‌معنای موفقیت آزمون یکپارچه نیست؛ وضعیت اجرای آن در رایانهٔ مالک هنوز گزارش نشده است. هیچ تغییر VPS یا DNS انجام نشد.

## اقدامات و خروجی‌ها

- `scripts/xennic-preview-isolated-test.sh` checkout مستقل نسخهٔ دقیق سایت و بستهٔ دارای checksum را در پوشهٔ خصوصی جدید می‌گیرد، دادهٔ مصنوعی تولید می‌کند و پروژهٔ Docker منحصربه‌فرد می‌سازد؛ قبل از راه‌اندازی، Compose مؤثر، نبود پورت مستقیم و دامنهٔ شبکه را کنترل می‌کند. پس از خروج فقط همان project را متوقف می‌کند و volumeها را حذف نمی‌کند.
- طبق خروجی غیرمحرمانهٔ مالک، رایانهٔ Linux دارای Docker/Compose، فضای آزاد و معماری `x86_64` است؛ digest شاخص Caddy، Python و OAuth2 Proxy با مقادیر بسته تطبیق داشت و manifestهای `linux/amd64` مشخص بودند. digest شاخص Node و PostgreSQL نیز گزارش و فقط در کپی آزمایشی pin می‌شود؛ این بررسی رجیستری جای آزمون runtime یا تأیید امضای image را نمی‌گیرد.
- دو سناریوی Origin غایب به کپی موقت test افزوده می‌شوند. هیچ فایل سایت یا بستهٔ اصلی تغییر نمی‌کند. gate این آزمایش مصنوعی است؛ OAuth/GitHub واقعی را تأیید نمی‌کند.

## آزمون‌ها و شواهد

| مورد | محیط و تاریخ | نتیجه |
|---|---|---|
| بررسی `bash -n` و parse کدهای Python تعبیه‌شده | Sandbox، ۲۰۲۶-۱۰-۳۱ | موفق؛ فقط syntax، بدون اجرای مراحل اسکریپت |
| خروجی `ss` و Docker/Compose و registry | گزارش مالک، ۲۰۲۶-۱۰-۳۱ | پورت ۴۴۳ در خروجی بدون شنونده بود؛ project/volume/network اولیه صفر گزارش شد؛ بررسی مجدد هنگام اجرا ضروری است |
| آزمایش اسکریپت و یکپارچهٔ Caddy/Payload | رایانهٔ مالک | هنوز گزارشی دریافت نشده؛ موفقیت یا شکست قابل ادعا نیست |
| gate واقعی، مرورگر، HTTPS عمومی، VPS/DNS | محیط نهایی | اجرا نشده و خارج از آزمایش مصنوعی است |

## ریسک‌ها و کارهای باز

- پس از اجرای مجاز مالک فقط نتیجهٔ هر مرحله و خطاهای پالایش‌شده دریافت و بررسی شود، نه فایل env، رمز، Cookie، token یا لاگ خام. در خطا مراحل وابسته متوقف می‌شوند؛ در صورت ناکامی توقف project، وضعیت آن جداگانه باید بررسی شود.
- برای پذیرش نهایی، آزمون gate واقعی و عدم bypass، ورود Staff و API، دسکتاپ و موبایل و دو دستگاه مستقل همچنان لازم‌اند. آزمون مصنوعی جایگزین آن‌ها نیست.
- نسخهٔ نهایی شبکه و egress OAuth، scope، DNS/TLS، منابع، backup و rollback باید پیش از اجرای VPS جداگانه بررسی شوند. مجوز فعلی شامل تغییر VPS یا DNS نیست.

## تصمیم‌ها و درخواست از مدیرکل

مالک از مسیر ثابت GitHub اسکریپت را دریافت و در رایانهٔ محلی اجرا کند؛ فقط وضعیت `PASS`/`STOP` و مرحلهٔ ناموفق را گزارش کند. دستور مالک برای استفاده از Caddy، OAuth2 Proxy و GitHub OAuth برای حساب مشخص مبنای طرح است، نه مجوز استقرار.

## پیگیری Vault

Vault در این نشست فقط خواندنی است. تصمیم‌ها و تنظیمات عملیاتی نهایی در صورت نیاز در نشست جداگانهٔ Vault ثبت شوند؛ این گزارش جای آن‌ها را نمی‌گیرد.
