# گزارش توسعه: تشخیص شکست callback واقعی

- **تاریخ:** ۲۰۲۶-۱۰-۳۱
- **مبنا:** پیام ارسالی مالک «Sign-in could not be completed. Please try again or contact the administrator.»، فایل `routes.caddy` بستهٔ v1.1.2 و کد OAuth2 Proxy نسخهٔ `v7.15.5`.
- **وضعیت:** مالک متن شکست را گزارش کرد؛ خروجی اجرای ادامه، کد HTTP، وضعیت کنونی lab، جزئیات گواهی و علت گزارش نشده‌اند. هیچ نتیجهٔ موفق OAuth ادعا نمی‌شود.

## خلاصهٔ مدیریتی

متن عمومی با پاسخ حفاظتی مسیر callback Caddy سازگار است. آن مسیر هم خطاهای upstream از دستهٔ 4xx را به متن عمومی با 403 و هم خطاهای 5xx را به همین متن با 500 تبدیل می‌کند. این متن به‌تنهایی هیچ‌یک از خطای scope، مجوز کاربر، اتصال به GitHub، CSRF یا Client Secret را ثابت نمی‌کند. callback نباید با code قبلی reload/replay شود.

## اقدامات و خروجی‌ها

- `scripts/diagnose-real-oauth-callback.py` فقط به stdout/stderr زندهٔ gate همان پروژه، بدون stdin و بدون ارسال signal به container، attach می‌شود؛ log driver قبلی `none` باقی می‌ماند و هیچ container یا config تغییر نمی‌کند. attach نتیجه‌های گذشته را بازیابی نمی‌کند؛ تنها خروجی استاندارد تلاش تازه را مشاهده می‌کند.
- فقط چند label ثابت از پیام‌های ازپیش‌شناخته‌شدهٔ استاندارد چاپ می‌شوند. بدنهٔ خطا، URL، code، cookie، token و محتوای raw در حافظهٔ موقت فرایند دیده می‌شوند اما چاپ یا ذخیره نمی‌شوند. در خطای غنی‌سازی، فقط در صورت انطباق دقیق قالب کد v7.15.5، عدد HTTP غیرمحرمانهٔ upstream یا پیام ثابت رد username نیز به صورت label گزارش می‌شود.
- اسکریپت اتصال local Docker و یک container در حال اجرای gate با project/service و image و log driver مورد انتظار را کنترل می‌کند. در نبود آنها متوقف می‌شود، هیچ چیزی را مجدداً ایجاد نمی‌کند و هیچ وضعیتی را اصلاح نمی‌کند.
- auth logging در پیکربندی فعلی خاموش است؛ در برخی خطاهای 403 ممکن است هیچ label ظاهر نشود. سکوت stream، موفقیت login یا نبود خطا نیست. `READY` فقط نشان می‌دهد client بلافاصله خارج نشده و اتصال واقعی و دریافت خط آینده را تضمین نمی‌کند.
- می‌توان HTTP status سند callback فعلی را فقط با خواندن `performance.getEntriesByType('navigation')[0].responseStatus` در console همان صفحه گرفت؛ در Firefox قدیمی یا در نبود داده ممکن است عدد 0/undefined باشد. متن URL یا اطلاعات console خام نباید ارسال شود.

## آزمون‌ها و شواهد

| مورد | محیط و تاریخ | نتیجه |
|---|---|---|
| پیام عمومی | ۲۰۲۶-۱۰-۳۱، گزارش مالک | متن خطا گزارش شد؛ وضعیت HTTP و سایر مراحل ناشناخته‌اند |
| نگاشت 4xx/5xx | بررسی ایستای بستهٔ v1.1.2 | هر دو متن یکسان دارند اما status خروجی متفاوت است |
| دسته‌بندی خطا | کد OAuth2 Proxy `v7.15.5` | redeem و enrich خطای 500 می‌دهند؛ موارد دیگری نیز ممکن است باعث 403/500 شوند |
| diagnostic filter | agent، ورودی کاملاً ساختگی | سه تست آفلاین؛ دادهٔ ساختگی در خروجی ظاهر نشد و Docker با برنامهٔ fake جایگزین شد |
| attach به Docker واقعی و retry | انجام نشده | سازگاری اجرایی و دریافت خط نامعلوم؛ نیازمند گزارش مالک |

## ریسک‌ها و کارهای باز

- این ابزار code یا cookie را نمی‌فرستد و چیزی روی disk ذخیره نمی‌کند، اما برای دسته‌بندی، raw stream جدید را در حافظهٔ خصوصی خود می‌خواند. diagnostic به‌خودی‌خود فرآیند login یا وضعیت حساب را تأیید نمی‌کند.
- هیچ scope اضافی، از جمله `read:org`، اعطا نشده یا مجاز فرض نشده است. پیش از توسعهٔ مجوز، دلیل و تأیید مالک لازم است.
- تأیید issuer در پروفایل موقت، موفقیت login مجاز، حساب دوم، Staff/API/Origin، media/GraphQL/logout، دو دستگاه، RTL و موارد زیرساخت همچنان باز است. هیچ اقدام VPS/DNS انجام نشده است.

## تصمیم‌ها و درخواست از مدیرکل

در صورت بازبودن همان lab، یک تلاش **جدید** از sign-in در همان Firefox و گزارش تنها label ثابت و HTTP status کافی است. از ارسال صفحه، screenshot حاوی URL، log خام و credential خودداری شود. اگر lab بسته شده، بدون راه‌اندازی مجدد وضعیت اطلاع داده شود.

## پیگیری Vault

Vault فقط خواندنی باقی می‌ماند؛ پس از روشن‌شدن علت و نتیجهٔ واقعی، تصمیم‌های scope و زیرساخت در نشست مستقل پیگیری شوند.
