# آماده‌سازی انتقال امن درخواست استقرار

- **تاریخ و مبنا:** ۲۰۲۶-۱۰-۳۱؛ [PR #11](https://github.com/feerozmandi/xennic-website/pull/11) و قرارداد `META-INT-140` v0.7.0. تغییر در انتظار بررسی و CI است.

## انجام‌شده

- مالک endpoint مدیریتی تاریخی و IP وب پیش‌بینی‌شده را تأیید و fingerprint عمومی ED25519 را ارائه کرد. از روی خروجی ارسالی نمی‌توان تشخیص داد fingerprint از کنسول مستقل ارائه‌دهنده گرفته شده یا همان نشست SSH؛ تا تأیید منشأ مستقل، trust خودکار برقرار نمی‌شود. **اصلاح ۲۰۲۶-۱۰-۳۱:** وجود فضای backup یا قابلیت SFTP/SSH تأیید نشده و فرض نمی‌شود.
- برای سمت فرستنده یک client مستقل آماده شد؛ هنوز به workflow یا سرور متصل و فعال نشده است. این ابزار repository، commit، digest و run number را با validator بررسی می‌کند، فقط به endpoint ثابت و حساب اختصاصی قراردادی متصل می‌شود و `StrictHostKeyChecking=yes`، known_hosts اختصاصی، کلید اختصاصی، بدون agent/forwarding و بدون shell محلی را الزام می‌کند. فایل‌های اعتماد و کلید باید عادی، متعلق به runner و غیرقابل‌خواندن برای دیگران باشند.
- token کوتاه‌عمر registry فقط به stdin فرایند SSH داده می‌شود، نه argv، محیط فرایند SSH یا خروجی. پروتکل پیشنهادی stdin دو خط است: JSON غیرمحرمانهٔ manifest و سپس token؛ گیرندهٔ forced-command آینده باید هر دو را مستقل و با محدودیت اندازه تأیید کند. خروجی SSH از سوی client خام منتشر نمی‌شود. این client امنیت یا اجرای گیرنده، استقرار یا سلامت را به‌تنهایی اثبات نمی‌کند.
- چهار گروه آزمون manifest و پنج گروه آزمون client با token ساختگی و SSH mock در sandbox موفق بودند؛ این آزمون‌ها اتصال واقعی، آماده‌بودن known_hosts یا دسترسی GitHub Actions به VPS را اثبات نمی‌کنند. آزمون‌ها به CI اضافه شدند.

## موارد باز

- سرور به راه‌اندازی و بازبینی forced-command محدود، validator مستقل، قفل و ترتیب، GHCR pull، backup رمزنگاری‌شده/restore، migration، healthcheck و rollback نیاز دارد. اتصال به workflow پس از تکمیل و تأیید پیش‌نیازهای اجرایی انجام می‌شود؛ هیچ deploy خودکاری اکنون فعال نیست.
- تأیید مستقل fingerprint، وضعیت branch protection و Environment، مسیر شبکهٔ runner، نوع فضای خارج از VPS و امکان بازیابی آن، Caddy/Gate و DNS authority بازند. هیچ credential از مالک در گفتگو یا Git درخواست یا ثبت نشد و هیچ تغییری روی VPS/DNS انجام نشد.

## Vault

مرجع اجرایی Vault تغییری نکرد؛ ثبت شواهد و انتقال مسئولیت در نشست Vault جداگانه قابل پیگیری است.
