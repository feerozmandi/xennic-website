# زنجیرهٔ helperهای نصب‌شدهٔ پیش‌نمایش

- **تاریخ/مبنا:** ۲۰۲۶-۱۰-۳۱، [PR #13](https://github.com/feerozmandi/xennic-website/pull/13). SSH و deploy واقعی غیرفعال‌اند؛ VPS، DNS و دادهٔ عملیاتی تغییر نکردند.
- **نصب و ایمنی:** `scripts/install-preview-sftp-helper.py` تمام فازهای ثابت، `sftp-transfer` و ماژول‌های لازم را با مالکیت root و مجوز خصوصی نصب می‌کند؛ نصب موجود را بازنویسی نمی‌کند و sudoers یا SSH نمی‌سازد. `FixedRunner.verify_helpers` حفظ شده و ایمنی فایل‌ها را پیش از اجرا بررسی می‌کند.
- **مسیر:** `scripts/preview-deploy-backend.py`، transaction و journal فایل‌های اجرایی `/usr/local/libexec/xennic-preview/` شامل `release-check`، `pull-image`، `current-check`، `backup-verify`، `sftp-transfer`، `migrate`، `activate`، `health` و `rollback` را با قفل مشترک و عملیات ثابت به‌کار می‌گیرند. verifier در `preview-release-verifier.py` به run موفق push به `dev` و artifact همان run/attempt/commit/digest متکی است؛ pull قبل از توقف app است. migration به transition بازبینی‌شدهٔ root و hash فایل‌های migration تصویر و ledger قبلی محدود است. backup از age و SFTP موجود استفاده می‌کند؛ ciphertext قبلی پس از تطبیق با رکورد خودش حفظ می‌شود. rollback تنها با تأیید سازگاری انجام می‌شود و restore داده خودکار نیست.
- **شاهد دورریختنی:** [CI 41221524381](https://github.com/feerozmandi/xennic-website/actions/runs/41221524381)، کامیت `4fa656957d3214f34c99d03531c26c8a23abf286`، هر چهار job موفق و انتشار در PR اجرا نشد. `installed-sftp` همان controller و helperهای نصب‌شدهٔ root-owned را برای انتشار موفق به digest متفاوت، backup رمزنگاری‌شده و SFTP واقعی محلی، migration افزایشی مصنوعیِ سازگار، activation و health اجرا کرد؛ ثبت migration و ایجاد جدول آزمایشی بررسی شد. سپس پس از activation عمداً health شکست خورد و rollback سازگار به نسخهٔ سالم و حفظ DB، media و migration افزایشی آزموده شد. بررسی منفی مجوزهای helper و ماژول نیز اجرا شد. PostgreSQL، Docker، age و SFTP واقعی اما دورریختنی بودند. GitHub API، artifact، release، CA و registry **ساختگی** بودند و شاهد GHCR یا GitHub واقعی نیستند. این آزمون restore خودکار داده در rollback انجام نمی‌دهد؛ آزمون restore DB ایزوله جزئی از backup است.
- **پس از merge:** انتشار مجاز push به `dev` باید artifact شاهد ایجاد و همان digest `linux/amd64` را از GHCR واقعی pull/test کند؛ job `tests/preview-ghcr-pull-published-ci.sh` نیز pull با helper نصب‌شده را بررسی می‌کند. دسترسی واقعی verifier به API/artifact و token/مجوزهای آن هنوز با انتشار جدید آزموده نشده‌اند. PR نامطمئن secret انتشار دریافت نمی‌کند. اجرای بعدی باید شماره، commit، نام تصویر و digest واقعی را ثبت کند؛ موفقیت fixture جای این شاهد نیست.
- **ریسک و پیگیری:** preflight اتصالات جاری DB و کانتینرهای شبکه را بررسی می‌کند، نه اثبات نبود تمام writerهای آینده روی میزبان؛ ایزولاسیون واقعی باید جداگانه تأیید شود. bootstrap نسخهٔ نخست، ارتقای نصب موجود، جدول transition بازبینی‌شده، backup/restore واقعی خارج VPS، fingerprint مستقل، مقصد offsite و ورود امن تنظیمات همچنان لازم‌اند. پذیرش gate/OAuth، Staff، مرورگر و DNS انجام نشده است. Vault فقط‌خواندنی و مرجع `META-INT-140` v0.7.0 بدون تغییر است؛ در صورت نیاز ثبت رسمی نتیجه/موانع در نشست Vault پیگیری شود.
