# گزارش توسعه: مسیر یکپارچهٔ gateway

- **تاریخ گزارش:** ۲۰۲۶-۱۰-۲۹؛ ساعت محیط و GitHub تاریخ دیگری نشان می‌دهد.
- **مبنا:** PR پیش‌نویس #21، `17a012a`.
- **وضعیت:** با مجوز مالک PR ادغام، انتشار و verifier مستقل موفق شد؛ پذیرش عملیاتی و گذار VPS باز است.

## خلاصهٔ مدیریتی

راه‌اندازی پروژهٔ ثابت Caddy و OAuth2 Proxy به عملیات activation افزوده شده است. helper پیش از ثبت healthy هویت، image، فایل‌های ثابت، تنظیمات خصوصی، شبکه و نبود peer ناشناس را بررسی و پس از سلامت داخلی، حفاظت مسیرهای بی‌نشست را probe می‌کند. این تغییر تا CI یکپارچه و بازبینی کامل اثبات‌شده نیست.

## اقدامات و خروجی‌ها

- Compose مجزای ثابت فقط برای edge و gate، شبکهٔ اختصاصی gateway و شبکهٔ اختصاصی egress اضافه شده است؛ App، DB و gate پورت میزبان ندارند. Caddy تنها سرویس دارای mapping است. listener داخلی probe همان route محافظت‌شده را استفاده می‌کند.
- هویت project/service، image digest، فایل‌های config، network peer، mount و برخی تنظیمات runtime در همان helper بررسی می‌شوند. رمزها در فایل خصوصی باقی می‌مانند. محدودهٔ OAuth آزمایشی به‌معنی تأیید scope یا پذیرش OAuth واقعی نیست.
- CI زنجیرهٔ نصب‌شده فایل‌های آزمایشی می‌سازد، ولی شروع پروژهٔ واقعی gate را به همان helper واگذار می‌کند. آزمون peer ناشناس جداگانه حفظ شده است. نسخه‌های قبلی Compose و داده‌های VPS تغییر نکرده‌اند.
- پس از موفقیت اولیه، probe که در image نامزد اجرا می‌شد به Python معتبر میزبان منتقل شد؛ آدرس Caddy فقط پس از احراز هویت و شبکهٔ کانتینر گرفته می‌شود. پاسخ‌های denial و headerهای جعلی پیش از healthy بررسی می‌شوند. عدم دسترسی به شبکه نیز باید شکست بسته بدهد.
- برای آزمون درخواست مجاز در همان زنجیره، نشست صرفاً مصنوعی با کلید دورریختنی CI و الگوریتم نشست نسخهٔ ثابت OAuth2 Proxy تولید می‌شود؛ نه credential واقعی است و نه نشانهٔ ورود OAuth واقعی.
- گذار installer برای نصب فایل‌های ثابت gateway همراه Compose و helper افزوده شد: منبع با digest بررسی و هر مقصد موجود رد می‌شود؛ Compose و دو نسخهٔ قبلی helper محفوظ‌اند و شکست قابل‌دریافت، فایل‌های ایجادشدهٔ بدون تغییر را برمی‌گرداند. آزمون CI موفق شد؛ بررسی config/secrets عملیاتی هنوز باز است.

## خطرها و پیگیری

انتشار و verifier موفق‌اند، اما اینها اثبات آمادگی VPS یا OAuth واقعی نیستند. گذار installer برای وضعیت واقعی VPS اثبات نشده و تنظیم runtime OAuth و secretها را تهیه یا بازنویسی نمی‌کند؛ وجود فایل مقصد نامعلوم مانع است. قطع برق یا فایل نیمه‌نوشته به بررسی دستی نیاز دارد و اجرای مجدد کورکورانه مجاز نیست. اتصال SSH از Arena پیش از دریافت کلید سرور reset شد؛ بررسی‌های فقط‌خواندنی از مالک در نشست VPS خواسته شد. DNS بازگشتی در بررسی فعلی برای preview پاسخ NXDOMAIN داشت؛ اعتبار پنل و zone هنوز باید رسماً روشن شود. بررسی دوبارهٔ listener/NAT و ظرفیت، scope نهایی OAuth، پذیرش چند دستگاه و backup واقعی مستقل باقی‌اند. هیچ secret، volume یا سرویس موجود حذف یا تغییر نشده است.

## تصمیم‌ها و درخواست از مدیرکل

تصمیم تازه یا تأیید تکراری درخواست نمی‌شود. در صورت شکست CI، رفع نقص در همان شاخه ادامه دارد.
